## Critical

- [x] **#1 ズーム時に用紙内外判定が座標系ミスマッチで壊れる**
  - ファイル: `CanvasRepresentable.swift:729-741`(`DrawingTouchGate.gestureRecognizer(shouldReceive:)`)、`182-189`(pageRects生成)

## 追加分: テストランナー改善後に検出されたクラッシュ・競合バグ (2026-07-17 セッション)

- [x] **#21 Core Data エンティティ重複定義によるテストランタイムのクラッシュ (Unexpected Exit / Crash)**
  - ファイル: `PersistenceController.swift`
  - 現象: テスト実行中に `Multiple NSEntityDescriptions claim the NSManagedObject subclass 'NoteFile' so +entity is unable to disambiguate.` / `Failed to find a unique match for an NSEntityDescription...` が多発し、クラッシュ・不安定化する。
  - 調査結果(当初の原因仮説「Codegen重複」は誤り): `Codegen=Class Definition` 自体は問題なく、重複クラス定義があればコンパイルエラーになるがビルドは成功している。**真因は「モデルの多重ロード」**。`NSPersistentContainer(name:)` は呼ぶたびにバンドルからモデルを**新規ロード**する。テストは `PersistenceController(inMemory:)` を多数生成する(各Suiteごと)ため、`shared`/`preview` と合わせて `NSManagedObjectModel` が何個も生成され、生成済みサブクラス(`NoteFile`等)に対して複数の `NSEntityDescription` が名乗りを上げ、`NoteFile.entity()`/`NoteOutline.entity()`(FetchRequestで使用)が一意解決できず上記エラーになる。
  - 修正: `PersistenceController` に **共有の `static let managedObjectModel`**(`Bundle(for: BundleToken.self)` から `InfiniteCanvas.momd` を1度だけロード)を追加し、`NSPersistentContainer(name:managedObjectModel:)` で全コンテナに同一モデルを渡すようにした。
  - 検証: ユニットテスト69件合格 かつ **当該 CoreData エラーログが完全に消滅**(修正前は毎回多数出力 → 修正後0件)。コミット `57c49a3`。

- [x] **#22 UIテスト時の描画/操作ジェスチャ直後のハングアップ・突然の再起動**
  - ファイル: 各種 UIテストクラス (`PencilOnlyUITests.swift`, `ShapeAssistUITests.swift`, `TodoUITests.swift` 等)
  - 現象: XCUITest のペンドラッグ直後にアイドル待ちでフリーズ・突然再起動する。
  - 調査結果: **#21 の派生**。モデル多重ロードによる `NSEntityDescription` 曖昧化がアプリ側の例外/不安定化を招き、シミュレータの通信断・再起動につながっていた。もう一つの仮説だった「自動保存デバウンス(0.8秒)のメインスレッドブロック」は該当せず(`scheduleAutoSave` は `Task { Task.sleep }` の非同期でメインを塞がない)。
  - 修正: #21(共有モデル)の修正で解消。
  - 検証: タスクが名指しした gesture 系(`PencilOnlyUITests`/`ShapeAssistUITests`/`TodoUITests`)を**新DBで個別実行し、3件すべて合格・CoreDataエラー0件・クラッシュ/ハング0件**を確認。
  - 補足(別事象): フル一括実行での SIGKILL は主に「スクラッチテストが残したノートの蓄積」による起動負荷が原因(#21とは別。テスト衛生の問題)。UIテストはクラス単位+DBリセットで安定。
