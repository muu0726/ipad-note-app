# InfiniteCanvasApp 追加機能タスク

`追加機能プロンプト.md` の **5機能すべて実装・検証完了** 🎉
(①蛍光ペン背面化 / ②③ページマネージャー / ④しおり・目次 / ⑤-A ロック / ⑤-B グループ化)。
各項目は完了で `- [x]`、実装内容を追記済み。

## 共通の前提(現状アーキテクチャ)

- ページ幾何: `PageMetrics`(幅800 × 高さ1130、gap 20 → **ページピッチ 1150pt**)。`PagedLayoutCalculator` が
  縦横×見開きの4レイアウトを計算(`CanvasRepresentable.swift`)。通常ノートは現状 **横スクロール固定**。
- レイヤー構成: `背景patternView → 背面マーカー(CATiledLayer) → objectLayer → 前面インク(PKCanvasView本体)`。
  背景・オブジェクトは PKCanvasView(スクロールビュー)内部にコンテンツ座標で配置(GPU同期スクロール)。
- 手書き: `NoteFile.canvasData`(単一 `PKDrawing`)。オブジェクト: `CanvasObject`(`x/y/width/height`・`zOrder`・
  `kind`・`payload`・`isLocked` 済み。`note` 対多)。ビューポートは `OpenNotesSession.viewports[objectID]`。
- Undo: `CanvasUndoBridge`(PKCanvasView.undoManager)+ `CanvasObjectUndo`(オブジェクト操作を同一履歴へ登録)。
  ページ構造変更は `CanvasObjectUndo.registerPageStructureChange`(描画+ページ数を1グループでUndo)。
- 検証は verify スキル(XCUITestドライバ)+ 純ロジックはユニットテスト。シミュレータは必ず1台
  (`-parallel-testing-enabled NO -maximum-concurrent-test-simulator-destinations 1`)。

## ② サムネイル一覧(ページマネージャー) + ③ ページの並び替え・コピー ✅ 実装・検証完了

通常ノート(`noteType == "paged"`)の全ページを格子表示し、並び替え・複製・削除を行う `PageManagerView`。

### 実装結果
- [x] **#1 ページサムネイル生成器** — `PageThumbnailRenderer`(新規)。各ページ矩形にコンテキストをクリップし、
  背面マーカー→オブジェクト(`CanvasObject.drawInThumbnail` へ共通化、makeThumbnail も流用)→前面インクの順に合成。
  `image(from:)` の切り出しに依存せず全体を実座標で描いてクリップで確定。opaque フォーマットで縁の透明化を防止。
- [x] **#2 PageManagerView(格子一覧)** — `LazyVGrid` のサムネイル一覧シート。ツールバーに `page-manager-button`
  (`square.grid.2x2`)を追加して起動。サムネイルは操作のたび `regenerate()` で再生成。
- [x] **#3 ページ並び替え** — `.onDrag`/`.onDrop`(セル間ドラッグ)+ コンテキストメニュー「左へ/右へ移動」。
  座標再割り当ては純ロジック `PagePlan.reorder`(旧page→新page写像)+ `pageRect` 差分の平行移動。
- [x] **#4 ページ複製** — `PagePlan.duplicate`。対象ページの全 `PKStroke`(transform 平行移動)と `CanvasObject`(複製)を
  1ピッチ後ろへ挿入、後続ページを押し出し、`pageCount += 1`。
- [x] **#5 Undo/保存の1グループ化** — オブジェクトの移動/削除/複製(`CanvasObjectUndo.registerFrameChange/Delete/Insert`)
  + 描画・ページ数(`registerPageStructureChange`)を同一ランで登録し1グループ化。`NoteCanvasView.applyPagePlan`。

### 検証
- ユニット: `PagePlanTests`(並び替え/複製/削除の写像・平行移動・ページ判定 5件)、
  `PageThumbnailRendererTests`(ページ範囲クリップ 1件)。全 67 件合格。
- 実機: ページマネージャーを開き 複製→2ページ化→削除→1ページ化 を XCUITest で確認(サムネイル格子表示・
  コンテキストメニュー・Core Data 反映)。※ scratch テストは確認後削除。

### 既知の残課題(次段で対応してもよい)
- ページ複製後、`pageCount` 増加で最終ページへ自動スクロールする(既存のページ追加挙動)。中央ページ複製時に
  やや違和感。必要なら複製時はスクロールしないよう調整。
- PDF 背景ページ(`isLocked` 画像)も複製/並び替えに追従する(オブジェクトとして扱うため動作するはずだが未実機確認)。
- ドラッグ並び替えの実機ドラッグは XCUITest 非対応のため、コンテキストメニュー「左右移動」で検証(ドラッグ自体は目視推奨)。

## ⑤-A ロックのユーザー解放 ✅ 実装・検証完了

システムロック(PDF背景など)とユーザーロックを **区別** して実装(ユーザー選択済み)。

### 実装結果
- [x] **#10-lock スキーマ** — `CanvasObject.isUserLocked`(Bool)追加。`isLocked`(既存)= システムロック(PDF背景・完全非対話)。
  `CanvasObject.isMovementLocked`(= `isLocked || isUserLocked`)ヘルパー。
- [x] **#12 ロック/解除** — 長押しメニューに「ロック」(通常時)/「ロック解除」(ロック中)。ロック中は右上隅に南京錠バッジ
  (`object-lock-badge`、タップで解除)。移動(`gestureRecognizerShouldBegin`)・リサイズ(ハンドル非表示)・テキスト/Todo編集・
  個別削除(メニューに出さない)を拒否。選択枠は出るので解除操作は可能。`ObjectLayerView.swift`。
- [x] **#13 投げ縄との連動** — `moveObjectsWithLasso`/`deleteObjectsWithLasso` を `!object.isMovementLocked` で除外。
- [x] 配線 — `onToggleUserLock`(CanvasRepresentable → NoteCanvasView.`toggleUserLock` で `isUserLocked` トグル即時保存)。

### 検証
- ユニット 69 件合格(スキーマ変更で回帰なし)。
- 実機(XCUITest): テキスト挿入 → 長押し「ロック」→ 南京錠表示 → バッジタップ解除 → 再ロック → メニュー「ロック解除」を確認。
  南京錠バッジ・選択枠表示・リサイズハンドル非表示も目視確認。※ scratch テストは確認後削除。

### 既知の残課題 / 留意点
- ロック/解除は Undo を積まない(モード切替のため。bookmark と同方針)。
- `deleteLastPage`(ページ削除)はロックオブジェクトも消す(ページごと消す構造操作のため意図的)。
- システムロック(PDF背景)は従来通り完全非対話で南京錠を出さない(`isUserInteractionEnabled=false`)。

## ⑤-B グループ化(Grouping) ✅ 実装・検証完了

### 実装結果
- [x] **#10-group スキーマ** — `CanvasObject.parentGroupID`(UUID?)追加。`CanvasObjectItem.parentGroupID` 経由で ObjectLayer へ伝搬。
- [x] **複数選択インフラ** — `ObjectLayerUIView` の `selectedID` → `selectedIDs: Set` へ拡張(`selectedID` は単体時のみの計算プロパティで互換維持)。
  タップ=グループ全体/単体を選択、長押し=単体を選択に追加(2つ以上ためられる)。選択中の全メンバーを青枠表示。
- [x] **#11 グループ化/解除** — 長押しメニュー: 2つ以上選択で「グループ化」(共通 `parentGroupID` 付与)、グループ選択中は「グループ解除」。
  `onGroupObjects`/`onUngroupObjects` → `NoteCanvasView.groupObjects`/`ungroupObjects`(即時保存)。
- [x] **一括移動** — グループ/複数選択中に1つをドラッグすると `ObjectLayerUIView.moveSelection` が全メンバーを平行移動。
  各メンバーの frame 変更を同一ランで `onFrameChanged` → `registerFrameChange` し **1 Undo グループ**。
- [x] **一括削除** — メニュー「削除」は複数選択時 `deleteSelection`(各 `onDelete` → Undo 1グループ)。

### 検証
- ユニット 69 件合格。実機(XCUITest): テキスト2個を離して配置 → A選択+B長押しで「グループ化」→ A ドラッグで **A・B が一緒に移動**
  (両者の frame 移動を検証)→ 長押し「グループ解除」→ 解除後はメニューに「グループ解除」が出ないことを確認。※ scratch テスト削除済み。

### 既知の残課題 / MVP の割り切り
- グループ化/解除自体は Undo を積まない(ロック同様のモード変更扱い。移動・削除は Undo される)。
- **リサイズは単体選択時のみ**(グループ/複数選択ではハンドル非表示)。グループ一括リサイズは未実装。
- 一括移動はスナップ無し(単体移動はスナップあり)。
- 複数選択の作成は「タップ+長押し追加」方式(投げ縄でのオブジェクト囲み選択は PencilKit ストローク投げ縄と競合するため不採用)。
- グループに含まれるロック済みメンバーも一括移動では一緒に動く(グループ優先)。

※ 各機能は「データモデル → 純ロジック(ユニットテスト) → UI → XCUITest検証」の順で、1機能ずつ
ビルド・テスト・シミュレータ検証しながら進める。
